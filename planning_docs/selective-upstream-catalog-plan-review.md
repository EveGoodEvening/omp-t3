## Findings requiring resolution

### C1 — Fix: make standalone diagnostic context reachable, not just a helper option

**Evidence:** local `parseArgs` recognizes `--check` only for one or two total arguments and returns no discovery args. `bin/omp-t3:115–117` constructs a default manager. Upstream changes this to `{ ompPath }` only. A helper accepting `ompArgs` does not make `omp-t3 --check --config overlay.yml` work: that three-argument invocation currently enters proxy mode. `--check --profile=work` recognizes check but drops the profile. Neither behavior meets an explicit-context diagnostic contract.

**Required plan amendment:** include the minimal `src/cli.js` helper parsing/caller migration needed to pass supported diagnostic context into discovery. Remove the local `--check` flag, preserve repeated overlays and argument boundaries, and do not apply proxy delegation/tool probing to diagnostics. Define supported syntax and invalid/missing-value behavior before coding. Alternatively, explicitly decide that only process cwd/environment are public diagnostic inputs and that overlay context is an internal API; that is a contract decision requiring re-review, not an implicit omission.

**Validated source assumptions:** the installed models command accepts repeatable `-e`/`--extension`, `--config`, and `--no-extensions`; explicit extensions still load with ambient discovery disabled. Profile preprocessing supports `OMP_PROFILE`/`PI_PROFILE` and explicit `--profile` precedence. Converting cwd into child `cwd` avoids forwarding a models-subcommand flag it does not declare. Preserve supplied environment rather than reconstructing credentials/profile variables. Preserve overlay order and relative-path resolution. Standalone is a new discovery context, not an assertion of equivalence with a previously running session. In particular the current proxy forcibly sets `PI_CODING_AGENT_DIR` while upstream changes that behavior; do not import that unrelated environment-precedence change accidentally.

**Acceptance:** invoke the actual diagnostic entrypoint with an isolated recording fake executable and explicit relative cwd, profile overriding inherited profile, repeated config/extensions (split and equals syntax), and `--no-extensions`. Assert the discovery process receives literal argument values, expected cwd/environment, and excludes proxy/session/tool flags. It must run diagnostics rather than start an RPC session. Missing values must fail observably, not silently switch contexts. A helper-only record test is insufficient.

### C2 — Fix: specify both sides of the catalog transport limit

**Evidence:** current and upstream frame tests use only 100 small models and assert less than 500 KiB. Neither establishes safety at the 1 MiB limit. `createModelResponse` duplicates the list in `data.models` and top-level `models`; retained names/IDs and list cardinality are unbounded. `--check` prints “well within 1024 KB” without checking. Crucially, OMP defaults to protocol 1: its encoder replaces a response exceeding 1,048,576 bytes including newline with an error *before the shim can prune it*. `get_available_models` returns the raw session catalog. Protocol 2 uses chunk frames; this slice's JSONL catalog handler does not reassemble them. The installed overflow error also omits non-string IDs (`rpc-frame.ts:281`), unlike normal responses that use `command.id`.

**Required plan amendment:** define the size check on the final UTF-8 serialized T3 frame including newline and both compatibility fields. If the complete pruned success cannot fit, return a small explicit failure with the original available ID; never truncate silently, claim success, or emit an oversized frame. Make diagnostic PASS/FAIL reflect this check. Document that upstream protocol-1 overflow remains a real failure, cannot be repaired by pruning downstream, and may already have lost an ID. Do not promise numeric-ID recovery when OMP omitted it. Do not silently introduce protocol negotiation/chunk support in P2; if oversized upstream catalogs must succeed, that needs a separate reviewed design.

**Acceptance:** exercise the actual downstream pipeline with a schema-heavy source and verify only the pruned frame reaches T3; exercise retained fields/cardinality that make the *duplicated output* exceed the limit, including multibyte text, and verify a bounded failure instead of connection-killing output. Cover just-under/over boundary serialization, not JS string length. Forward an OMP transport-limit failure unchanged; no CLI fallback, ID fabrication, or retry. State protocol-2/chunk handling as unverified/outside this port rather than claiming universal catalog support.

### C3 — Fix: define malformed catalog members and valid empty catalogs

**Evidence:** explicit non-array `data.models` handling is proposed upstream, but unchanged `pruneModels` reads `item.provider` and calls `id.startsWith`; `[null]` or `{ id: 7 }` throws inside the readline callback. An explicit shape error must not turn a malformed provider response into a process crash. Upstream live handling accepts `[]`, whereas standalone treats an empty list as diagnostic failure; this distinction is reasonable but currently implicit.

**Required plan amendment:** require a successful response with `data.models` array and entries usable by the existing ModelInfo projection. Convert invalid members into one explicit catalog failure rather than silently skipping entries or allowing exceptions to escape. Preserve valid empty session catalogs as `success: true` with empty arrays; allow standalone check to fail explicitly because it found no usable selectable models. Distinguish request IDs from model IDs: numeric/string *request* IDs must be preserved; numeric model identifiers need not be coerced into invented strings.

**Acceptance:** malformed/missing/null/object `data.models` and arrays containing null or incompatible ID/provider values produce a correlated explicit failure and no models. A subsequent unrelated streaming frame still passes, proving the proxy remains alive. `data.models: []` returns the decided live-empty contract, while standalone empty output returns the decided diagnostic failure. Existing permissive defaults for valid string identifiers/selectors should not be accidentally removed.

### C4 — Fix: settle unsupported thinking behavior instead of retaining a fabricated ladder

**Evidence:** 0088817 correctly selects arrays or `thinking.efforts`, but leaves local `thinking === true` synthesizing low/medium/high. AC2 says supported levels only. Boolean capability alone does not establish those three levels. The new efforts-object branch also makes the no-efforts/budget-only case relevant.

**Required plan amendment:** state the legacy boolean/no-efforts contract explicitly. Recommended: emit only advertised effort mappings; preserve `reasoning` without inventing effort support when no array is present. If backward compatibility requires the old boolean ladder, identify supported source evidence and document the exception rather than claiming unsupported levels are excluded universally. An empty advertised array must map all supported T3 ladder keys to null; unknown levels must not enable other options.

**Acceptance:** CLI array and RPC efforts-object representations of the same advertised levels yield the same map; advertised `xhigh`/`max` survive, absent `off`/minimal/other levels remain null. Cover an empty array, unknown effort, and boolean/no-efforts object according to the chosen contract. Keep role-default `target.options.thinking` independent: catalog projection must not rewrite the resolver or caller-supplied options.

## Verification and isolation plan

1. Use existing stream-based e2e fixtures for the catalog request/reply path and preserve the full-turn/skills behavior they already exercise. Add targeted regression tests only for the consumer-visible uncertain edges above; do not add source-string, wiring-only, arbitrary small-size or list-length-only assertions.
2. Diagnostic gate must execute the actual `bin/omp-t3 --check` surface, but with scratch HOME, XDG cache/config/state, OMP/Pi agent/config locations, cwd and controlled fake OMP. `bin/omp-t3:128` creates the real session symlink when HOME is real. The shell-path test currently isolates HOME only; explicitly isolate inherited XDG/agent/profile paths too. Recording fixtures must return meaningful valid catalog data for success and separate failure cases.
3. Mock/inject the doctor for in-process failure tests, or disable issue creation through its existing instance option; for subprocess gates shadow `gh` with a controlled fixture and remove real authentication exposure. `issuesEnabled` defaults true and the current doctor invokes `gh auth status`/`gh issue create`. Scratch HOME alone is not a guarantee when inherited auth/environment remains. Use synthetic errors, never credential-bearing real stderr.
4. Do not launch installed OMP merely to demonstrate argument propagation: standalone model listing initializes auth/settings, loads extensions and can fetch providers (`models-cli.ts:335–367,401–426`). A fake diagnostic proves shim behavior only; disclose that it does not establish installed-provider availability or live T3 UI behavior. No paid requests or real issues are needed for P2.
5. Targeted gate after implementation: catalog, e2e, CLI and check-shell tests; include launcher/delegate-model/extension-policy compatibility tests for touched paths. Final project gate is `npm test`; package scripts expose only `test` and `check`, not build/typecheck/lint. `npm run check` must use the isolated environment above, never the user's default HOME. AC6 still requires independent implementation review and the later final-union gates; this static plan review satisfies neither.

Do not copy upstream fork/release/delegation/queue claims.
