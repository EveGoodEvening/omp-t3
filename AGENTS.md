# AGENTS.md — omp-t3

## Versioning

Release tags are plain semver `vX.Y.Z` (the prerelease `1.3.0-N` scheme ended with 1.3.0-6). When npm already holds the plain base (for example `1.4.0`), later shim iterations use the `<base>-<N>` prerelease form (`1.4.0-1`, `1.4.0-2`, …) so each publish is a distinct, npm-legal version. npm publishing and the Homebrew tap (`hashangit/homebrew-omp-t3`) are manual owner steps.

## Subagents

For long-running delegated tasks, use T3's `delegate_task` MCP tool (target `providerInstanceId: "pi"`) instead of the native `task` tool so child sessions are created as openable T3 threads.

Omit `target.model` to use OMP's configured subagent models (`task.agentModelOverrides` by `role`, then `modelRoles.task`); see README "Subagent model selection".

## Lessons

- Security audit (2026-11-04, HEAD `0549e5e`): all 16 files in the published `omp-t3@1.4.0-5` tarball matched the checkout, and its SHA-256 matched both Homebrew formulas. This verifies that artifact only, not future publishes or external OMP/T3 components. npm's `latest` was `1.3.0-4`; `beta` was `1.4.0-5`.
- `ContractDoctor` enables automatic GitHub issue creation by default using existing `gh` authentication. Discovery error messages enter the issue body without redaction; truncation and the label "sanitized" do not establish privacy. Security reproductions must mock `gh` and use synthetic data.
- T3 0.1.7 adds `--offline` to short-lived Pi discovery (`--mode rpc --no-session --offline`), but OMP 18.16.0 rejects that flag with exit code 2. Normal chat does not use the hint, so chat can work while provider models and skill/extension-command menus are empty. The shim must consume the Pi-only hint without disabling OMP resource discovery; this does not provide network isolation.
- Fork installation smoke (npm 12.2.1): `npm install -g .` links to the checkout, while a Git URL installs a copy under the global npm root and is classified as `npm` by self-update. npm 12 defaults `allow-git` to `none` (`EALLOWGIT`); a trusted Git source requires command-scoped `--allow-git=all`. Fork updates must use the original checkout/URL, not the updater's upstream `npm update -g omp-t3` suggestion.
- Subagent model lists are opt-in: unset/empty `OMPT3_SUBAGENT_ALLOWED_MODELS` and `OMPT3_SUBAGENT_DISALLOWED_MODELS` disable the shim model-policy prompt and guards. Nonempty inherited environment variables still enable them; AGENTS.md instructions and delegation routing are independent.
- Rebasing `dev` onto `main` (2026-11-12): `main` 1.5.0 (`fa055d7`) and `dev` (`1f6ebf7`) each added an `--offline` branch to `src/cli.js`'s arg loop. Git merged both silently, leaving the second branch unreachable. After rebasing these branches, check for semantic duplicates, not just textual conflicts. Commit messages here must not carry AI co-author attribution trailers; a PreToolUse hook blocks such commits.
- Never interpolate an executable path into `execSync`, even double-quoted: `$(...)` and backticks still run. Use `execFileSync(path, args)`. `--check` in `bin/omp-t3` was the last such call site; `test/check-shell.test.js` puts the fake `omp` under a `$(touch …)` directory to guard it. `which omp` in `src/cli.js` uses a constant string, which is safe.
- T3 `delegate_task` knows nothing about OMP's `modelRoles.task`/`task.agentModelOverrides`; an omitted `target.model` inherits the parent model. `src/delegate_models.js` fills it inside the adapted bridge from `pi.pi.settings` (`getModelRoles()` plus `mirrorState()` layers; OMP 18.20.0 does not export the `task.agentModelOverrides` setting handle). Its source is embedded via `toString()` into both the bridge and the policy hook, so it must stay self-contained. Objects returned from `vm` contexts are not `deepEqual` to host-realm literals; compare them through JSON.
- T3 v0.1.9 (`24e77473ecf41bc1f7142529c7911c1c1aae1d76`) enables five lower thinking levels for absent/partial maps on reasoning models. Emit all seven keys, with explicit nulls for every unadvertised effort; CLI arrays and RPC `thinking.efforts` are equivalent. This is catalog advertising, not permission to clamp caller/role options.
- Catalog frame limits must measure final UTF-8 JSON plus LF, including both `data.models` and top-level `models`; each individual list can fit while the duplicated response overflows. OMP protocol-1 overflow can happen before pruning; preserve that real failure without guessed IDs or CLI fallback.
- Synthetic diagnostics: `node test/check-fixture.js "$(command -v npm)"` runs `npm run check` with scratch HOME/XDG/Pi/OMP directories, a recording literal-path fake OMP and rejecting fake gh. Its controlled PATH needs both Node and `sh` for npm lifecycle scripts; no inherited secrets or installed OMP are needed. Fixture cleanup runs in `finally`.
- Atomic Stop uses `src/queue.js` through the proxy's single `outputRecords` writer. Classify `get_state` only after the ordinary pending-count projection: T3 v0.1.9 considers any finite nonzero count (including negative/fractional values) busy, invalid counts default to zero, and nonliteral `success:true` takes the failure-sensitive path. A Promise batch parser is adversarial scheduling evidence, not Effect/live-T3 equivalence.
- Stop failures require a real process owner: SIGKILL the owned main child before stdin closure, observe `exit` rather than `killed`/`close`, and bound non-reading-output/retained-pipe observation. Restore/watchdog timers need captured-identity guards as well as cancellation; an already-queued old callback must not affect a newer prompt or Stop. Synthetic owner fixtures deliberately model EOF draining accepted work.
- Async doctor fixtures must retain their temporary `XDG_STATE_HOME` through Promise completion, not restore it in a synchronous `finally`. Otherwise a delayed watchdog can persist state under the inherited state home. Run pipeline/doctor checks with a scratch HOME/XDG environment as an outer isolation boundary too.
- T3 RPC waiters match exact string ID, not response command. State destination correlation must precede catalog/command adapters and use ordinary state projection without rewriting command/ID/outcome. Keep the correlation table count/byte bounded; malformed command labels can otherwise bypass the Stop fence.
- Node readline forwards readable errors on the Interface before later input listeners. Handle both Interface and readable errors explicitly. Keep Stop failure ownership through release writes; a real non-reading Writable (not callback counts) proves backpressure admission.
- Pipeline embeddings use inert doctors; real-doctor regressions always construct inside scratch state and disable issues with a controlled version. An outer HOME/XDG boundary is additional protection, not fixture hermeticity.
- `Writable.write(true)` proves admission, not completion. Stop retains failure ownership until admitted output callbacks succeed, bounded by its existing fence; terminal bookkeeping waits for successful completion. A retained state `_write` callback can fail after a terminal was queued but before its `_write` ever runs. Keep old delivery failure ownership across an accepted new prompt, while generation/transaction/disposal guards prevent old cleanup from touching the new doctor's/hold-open lifetime. Ordinary transport retirement must also notify the direct-process owner: closing readlines alone leaves a persistent child orphaned.
- Live routing uses the existing content-keyed generated policy hook, not a built-in tools allowlist. Installed OMP 18.20.0 preserves stable enabled membership and mounted docs through public get/set; concurrent registry/mount changes can lose membership/presentation. Lifecycle filtering failure must keep a headless diagnostic and the independent native-task call guard.
- Required generated-hook registration is acknowledged on the owned final child's fd 3 before admitting RPC/output. Extension loader errors alone are not refusal (OMP can continue); file-write failure refuses before spawn, missing registration refuses the single child without probes/replacements. Drain acknowledgement bytes after process exit before judging registration, since process exit and pipe delivery are separate observations.
- Generated-hook identity must survive OMP's loader transformations: `import.meta.url` did not identify the original generated file in the isolated OMP 18.20.0 loader proof. Embed a digest of canonical generated source, separately hash final source for the cache filename, and pass the selected contract identity through CLI/bin/proxy. Clear the old fd environment field so cached old hooks cannot consume/close the new private channel.
- Registration deadlines belong to the decision, not direct-child `exit` or descendant-delayed `close`. Drain queued acknowledgements before judging close, keep the ten-second deadline until registration, and retire only owned signal-forwarding handlers before mirroring child signals. Catalog error envelopes need the same UTF-8/escaping/ID/LF bound as successes; omit optional detail before giving up correlation, then use the mandatory owned-transport failure path if even that cannot fit.
- A real child's `appendFileSync` is synchronous only within that child: another process can observe the created file before its contents are written, then SIGKILL it in that gap. Owner failure fixtures must await a child-issued completion witness after the append returns, not poll file existence. Keep that witness off the deliberately blocked/faulted output channel and bound its wait with the existing test deadline.
